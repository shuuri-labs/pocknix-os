# AGENTS.md

Instructions for coding agents working in this repo. [CONTRIBUTING.md](CONTRIBUTING.md) has
the same rules with the detail; read it before your first change.

## Before you change anything

- Read "Where changes go" and "Package rules" in [CONTRIBUTING.md](CONTRIBUTING.md). The dir a
  change lives in decides whether it ever reaches users.
- Never edit `vendor/` (regenerated by `make sync`) or a kernel's synced `config`; kernel options
  go in a delta.
- Fixes go where they stick: a package, a systemd unit, the session launch path. Never a one-off
  edit on a device.

## While you work

- Bump `pkgrel` for every package whose shipped contents change.
- A new package name gets a `depends=` edge from its layer metapackage in the same change.
- Code comments: one line, WHY only; two when a trap needs its cause.
- A doc that describes what you changed is updated in the same commit.
- Run `make check` before every commit and fix what it reports. Never work around a check; an
  allow-file row needs a real reason.
- Commits: `area: concise summary`, one finished change each.

## The PR

- The body is the template's sections and nothing else: What, How, Tested, How to test, the
  checklist. Short and casual, about 200 words outside code blocks ("What the PR must contain").
- **How to test** is required: exact build and install commands, numbered steps, what the
  reviewer should see, how to roll back.
- **Tested** shows the change ran on real hardware, with evidence (a log excerpt, a screenshot,
  numbers). Never claim a device test that didn't happen; code nobody ran isn't ready for a PR.
- Say the PR was written with AI assistance.
- Never sign or publish packages; releases are the maintainer's.
